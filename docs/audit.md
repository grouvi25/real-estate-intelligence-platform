## Ре-аудит доступности функций (сквозная проверка «функция есть → до неё можно дойти»)

Проверено послойно: все 12 роутеров смонтированы в `main.py`; каждый экран Mini App достижим (таб-бар: Обзор/Сигналы/Лиды/Объекты/Аналитика; `queue` — с дашборда, шапки сигналов и карточки сигнала; `settings` — шестерёнка на дашборде; детальные экраны — по тапу); все 27 методов API-клиента, используемых экранами, определены и указывают на реальные эндпоинты; поля ответов совпадают с тем, что рендерит UI; каждая Celery-задача из `.delay()` зарегистрирована (брокер починен, проверено сквозняком).

Найдено и **исправлено**:
- **Безопасность/изоляция агентств:** роутер `signals` работал без manager-auth (agency_id брался из запроса клиента) — любой клиент мог читать/действовать с сигналами чужого агентства (raw-текст покупателя = ПД). Теперь все 6 эндпоинтов signals требуют JWT и скоупятся по агентству из токена. Проверено на проде: без токена → 401, с токеном → 200.
- **Сломанный флоу реферала:** кнопки «Принять/Отказать» в уведомлении партнёру вели на несуществующие `{base_url}/referrals/{id}/accept|reject` (нет префикса `/api`, нет эндпоинта). Добавлены `GET /api/referrals/{id}/accept|reject` (публичная magic-ссылка: pending→accepted/rejected, уведомление направившего менеджера, страница-подтверждение), URL кнопок исправлены. Проверено: эндпоинт достижим.
- **Живучесть Mini App:** токен (TTL 7 дней) кэшировался и не обновлялся — после истечения все запросы падали в 401 без восстановления («не зайти никуда»). Теперь при 401 клиент сбрасывает токен, один раз ре-аутентифицируется по initData и повторяет запрос.
- **Недостижимая функция:** `PATCH /partners/{id}` не имел UI — добавлена кнопка Включить/Отключить партнёра в разделе Профиль.

Минорные (задокументированы, не блокируют):
- Дублирующие неиспользуемые UI эндпоинты: `PATCH /leads/{id}/matches/{property_id}` (UI использует `POST .../feedback`; оба учитываются движком матчинга) и `POST /geo/agencies/{id}/geo` (онбординг-путь; UI использует `POST /geo`).
- Ветка гео `partner_offer` ссылается на `POST /api/partners/accept` (не реализовано) — редкий случай добавления города, защищённого партнёром.
- `rematch_on_price_change` учитывает исключения из `buyer_profile`, но не из таблицы `match_exclusions` (UI пишет в profile, поэтому отклонения из UI учитываются).
- Вебхуки Telegram/MAX — заглушки: бот работает на исходящие уведомления + запуск Mini App, входящие команды/колбэки не обрабатываются (допустимо для модели «Mini App как интерфейс»).
- **Приток сигналов:** объекты `Signal` создаются только Telegram-коллектором (Telethon, выключен без ключей) или сид-данными. HTTP-эндпоинта приёма сигналов нет, планового поллера для адаптеров классифайдов/VK нет. Значит до включения Telethon (или добавления ingest-эндпоинта/поллера) экраны Сигналы/Очередь не имеют живого источника данных.
- `signalDetail`/`propertyDetail` грузят список и ищут по id (нет `GET /{id}`) — работает, чуть неоптимально.
