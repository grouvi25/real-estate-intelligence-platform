# Единый чек-лист приёмки (ТЗ раздел 35)

Финальная сводка по всем блокам системы. Статусы: ✅ готово · ⚙️ частично · ⏳ впереди

**35.1 Инфраструктура.** ✅ Docker Compose (dev-стенд, namespaced `reip`), CI/CD на VPS, секреты только в `.env`, HTTPS через общий nginx + Let's Encrypt (`https://reip.grouvi.online`), приложение слушает 8000 только на loopback.

**35.2 База данных и миграции.** ✅ 15+ таблиц, идемпотентный SQL-раннер миграций (001–008, 040–053), blind-index для дедупликации, представление `v_signal_to_outcome`.

**35.3 Безопасность и 152-ФЗ.** ✅ Fernet-шифрование ПД, HMAC blind-index, PII-анонимайзер перед AI, JWT (WebApp-HMAC), rate limiting на публичных эндпоинтах, verify webhook-secret.

**35.4 Мульти-гео и защита территорий.** ✅ Защита городов, резервирование, генерация ключевых слов (Celery), коллекторы Telegram (Telethon), ВК, YouTube и RSS — каждый включается при наличии своего ключа, иначе безопасный no-op.

**35.5 Сигналы и Signal Bus.** ✅ Приём/скоринг сигналов, `content_units`, воркфлоу ответа (draft→sent), адаптеры каналов (Avito/CIAN/Telegram/MAX/VK/YouTube/RSS), очередь триажа в Mini App: ответить, эскалировать, отклонить, квалифицировать. `origin_system`/`reply_channel`/`reply_status` и представление `v_signal_to_outcome` приведены к дополнению Signal Bus.

**35.6 Лиды и матчинг.** ✅ Квалификация с согласием, матчинг по весам ТЗ (бюджет +30, сегмент +25, локация +20, приоритеты +15, hot +10 — сверено), обратная связь по подборкам + жёсткие исключения, переподбор при смене цены (в т.ч. ночной проход по ценам, изменённым мимо API), альтернативщики. Права субъекта ПД: выгрузка (§14), удаление (§21), поиск по телефону через слепой индекс.

**35.7 Лид-магниты.** ✅ LM-1 (подбор), LM-2 (ипотека, 5 программ + маткапитал), LM-3 (проверка объекта), LM-4 (районы по сценариям), LM-6 (ROI аренды). Согласие + rate-limit на всех.

**35.8 AI и стоимость.** ✅ Двухступенчатый intent scoring, учёт стоимости в Redis, лимит бюджета (429) + алерт 90%, 11 промпт-модулей. ✅ Смена провайдера из кабинета, без перезапуска.

**35.9 Партнёры и Knowledge Moat.** ✅ Рефералы + истечение, запись исходов сделок, еженедельный пересчёт Source ROI и весов матчинга.

**35.10 Продуктовые расширения (ТЗ 32).** ✅ Decay скоринга, эскалация просроченных задач, детект «мёртвых» источников, UTM-атрибуция, CRM-вебхук экспорт, генерация КП/отчётов (HTML; PDF — опц. extra), аналитика (overview/funnel/managers/source-roi).

**35.11 CRM-интеграции.** ✅ Адаптеры Topnlab/amoCRM/Bitrix24/YUcrm + `agency_crm_config` (ключ шифруется), реестр адаптеров, экспорт при квалификации лида через выбранный агентством коннектор (generic-вебхук — запасной вариант), id сделки возвращается в лид и замыкает атрибуцию «сигнал → лид → сделка → деньги».

**35.12 Mini App и приёмка.** ✅ SPA (роутер + компоненты + 16 экранов, единая дизайн-система на переменных, светлая и тёмная темы), отдача статики, синтаксис-проверка в CI. ✅ 567 автотестов, `ruff`+`pytest`(Postgres+Redis)+node-check, авто-деплой на зелёных тестах. ✅ Ежедневный отчёт руководителю 07:30 + авто-алерт очереди Celery. ✅ Нагрузочный тест 50 RPS пройден (0 ошибок, p99 8.3 мс).

## Согласованные отклонения от манифеста ТЗ

Приняты заказчиком 08.08.2026, оба — формальные расхождения со списком файлов
в манифесте, а не пробелы в функциональности. Обоснование целиком — в
`docs/file_manifest.md`, раздел «Deviations».

- **`match_scorer.py` (AI-скоринг подбора) не реализуется.** Приёмочный пункт
  35.7 самого ТЗ требует весовую модель, и она реализована точно по весам.
  Файл упомянут в манифесте только именем: ни текста промпта, ни места вызова,
  ни критерия приёмки. AI при этом в подборе участвует — он разбирает и
  покупателя (`buyer_profile`), и объект (`object_analysis`), а веса
  доучиваются по закрытым сделкам еженедельно.
- **`source_scorer.py` отдельным файлом не выделяется** — оценка источников
  работает внутри `discovery/source_finder.py`.
